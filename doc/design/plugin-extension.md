# 插件扩展设计

> 状态：方向草案。

## 决策

通过统一的插件机制扩展 Agent Runtime。插件可以注册用户自定义的 Agent Loop Node、Control Node 和工具；模型接入、上下文策略和 skill 等扩展也应沿用同一套发现、加载、配置和生命周期机制。内置能力和用户实现遵循相同的节点契约。

## 扩展边界

插件接口需要明确说明：

- 输入、输出和产物引用；
- 配置与版本；
- 所需权限和可使用的工具、工作目录；
- 资源清理和错误语义；
- 能否报告模型调用、工具调用、检查结果和剩余待处理操作。

Runtime 在边界校验插件声明与产物，限制插件能够使用的资源，并记录插件执行结果。插件不能私下维护一份与会话历史脱节的权威记录。

插件如何隔离、是否支持热加载以及具体清单格式属于后续决策。若插件无法报告内部进度，Runtime 应明确记录其为不透明执行单元，而不能假装支持内部恢复或分叉。
