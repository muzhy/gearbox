# 工作流节点模型设计

> 状态：方向草案。

## 决策

工作流由节点和连接组成，可以包含循环。Runtime 负责启动节点、传递结果、限制允许的后继，并记录进度和停止原因。框架只定义两类节点的基本契约：**Agent Loop Node** 和 **Control Node**。具体工作流和节点实现主要由用户定义。

## 节点类型

| 类型 | 职责 | 典型输出 |
| --- | --- | --- |
| Agent Loop Node | 调用模型、使用工具、迭代处理分配的任务 | 产物、执行记录、完成或受阻状态 |
| Control Node | 执行编译、测试和其他程序检查，并依据已声明规则选择后继或结束 | 检查结果、证据、路由决定及原因 |

编译、测试和 Review 是工作流中的具体步骤，不是框架预设的第三类节点。Review 可以由另一个 Agent Loop Node 承担。

默认工作流可以只有一个 Agent Loop Node；只有在需要明确验证或分工时才增加其他节点。节点的输入、输出、状态和错误语义必须足够明确，才能由 Runtime 记录和继续执行。

## 示例

```text
Agent Loop Node：修改代码
        ↓
Control Node：编译、运行测试并给出检查结果
```

节点模型只规定工作流执行单元的边界；具体路由规则见[工作流路由](workflow-routing.md)，扩展方式见[插件扩展](plugin-extension.md)。
