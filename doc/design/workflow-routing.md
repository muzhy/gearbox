# 工作流路由设计

> 状态：方向草案。

## 决策

Control Node 必须根据实际执行的检查和预先声明的程序规则选择合法后继或结束。路由不能只相信 Agent Loop Node 的完成声明，也不能仅靠 Prompt 或 skill 要求模型自行验证。

## 路由规则

- 节点之间传递明确的任务输入、产物引用、检查证据和状态。
- Control Node 可按进程退出码、测试结果、文件检查或结构化产物校验结果路由。
- 给定相同的已记录状态和检查结果，路由应得到相同的决定。
- 失败、无法判定、超时和无后继都必须有明确出口。
- 每次回环受重试次数、模型调用次数或时间预算约束，避免无限循环。
- 检查命令可能失败、超时或产生不稳定结果；Runtime 记录观测结果，不把一次通过扩大解释为绝对正确。

Review 的意见可以作为输入，但是否继续或结束仍由工作流声明的规则处理。若路由依赖模型输出，程序必须先校验该输出并按已声明规则作出最终决定；这种判断不能称为确定性路由。

## 示例

```text
Agent Loop Node：修改代码
        ↓
Control Node：编译和测试
        ├─ 失败 → 将错误与证据交回修改节点
        ├─ 通过 → 进入后续检查或结束
        └─ 超时／预算耗尽／无法判定 → 停止并保留现场
```

路由依据本次实际检查结果，并保存命令、退出状态及必要的输出摘要。节点模型见[工作流节点模型](workflow-node-model.md)。
