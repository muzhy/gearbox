# 命令行参数设计

> 状态：设计草案；命令名称和具体选项以代码与帮助输出为准。

## 决策

命令行采用以下结构：

```text
gearbox [command] [options]
```

一次调用最多选择一条命令。命令位于程序名之后、所有选项之前；命令可以省略，省略时使用默认命令。不使用位置参数，工作区、任务和配置路径等输入通过选项传递。

## 参数语法

1. 以 `--` 开头的参数是选项。无值选项使用 `--name`，有值选项使用 `--name=value`，只在第一个 `=` 处分隔名称和值。
2. 不以 `--` 开头且首字符为英文字母的参数是命令候选，必须与已注册命令完全匹配。
3. 其他不以 `--` 开头的参数是非法输入。

选项值必须位于同一个参数中，因此 `--config=./config.toml` 合法，而 `--config ./config.toml` 不作为选项值解析。带空格的值由 shell 作为一个参数传入。

不使用单短横线选项、独立的 `--` 结束标记或位置参数。命令名称统一使用小写字母、数字和短横线，并以小写字母开头；命令不接受缩写或前缀匹配。

## 命令和错误

首个参数为已注册命令时选择该命令；首个参数为选项或没有参数时选择默认命令；未知命令候选、未知选项、缺少必需选项、选项值缺失或重复使用不符合规则时失败退出。

帮助请求不要求同时提供必需选项，也不执行命令操作。错误信息应指出选中的命令和出错参数，不输出 API Key 或完整配置内容。新命令不能改变已有显式命令的含义；默认命令或已有选项语义变化时需要评估脚本兼容性。

具体命令的选项、退出语义和示例由命令帮助及实现定义。
