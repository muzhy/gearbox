# 会话分支设计

> 状态：设计草案，尚未实现。
>
> 本文只决定会话历史如何从检查点创建、继续和切换分支。检查点的事件粒度见[会话检查点设计](session-checkpoints.md)；从旧点重新执行时如何处理外部状态见[分支重执行与外部状态设计](branch-reexecution.md)。项目总体定位见[gearbox 定位](../gearbox-positioning.md)。

## 1. 决策

新分支引用选定检查点及其祖先历史，原分支保持不变；新产生的事件、调用和费用只追加到新分支。沿原分支继续和从旧位置重新尝试是两种不同操作，后者必须产生新的分支身份和新的模型、工具调用身份。

会话树描述历史分叉关系，不等于文件系统、数据库或远程服务的复制。分支能否实际继续，还要核对检查点所引用的外部状态；具体重新执行规则见[分支重执行与外部状态设计](branch-reexecution.md)。

## 2. 可用的分叉点

默认只从“已提交、可继续且具有语义目的”的检查点开放分叉，例如：

- 进入或完成一个工作流 Node；
- Agent Loop Node 提交阶段性产物；
- Control Node 产生检查结果和路由决定；
- 用户明确要求从某个调用检查点另试一种路径。

调用仍在进行、响应尚未到达或工具仍在执行时不能创建可继续分支。一次调用完成也不自动意味着值得分叉；只有它形成独立的任务选择或证据路径时，才适合作为用户可见的分叉点。调用检查点和语义检查点的区别见[会话检查点设计](session-checkpoints.md)。

如果模型响应带有待处理工具，分支必须继承调用身份和待处理队列。从工具 A 结果后分叉时，工具 B 仍待处理；要放弃或改写队列，必须记录显式取消或重新规划，而不能静默丢弃模型协议状态。

## 3. 分支关系与历史

创建分支时：

1. 新分支记录父分支和所选检查点的身份。
2. 祖先事件按引用共享，不覆盖或重新标记原分支的事件。
3. 新分支追加自己的模型请求、工具调用、Node 执行和路由事件。
4. 原分支仍可继续；切换回原分支时恢复它自己的上下文和待处理状态。

兄弟分支不自动合并上下文或产物。若一条分支使用另一条分支的产物，应保存明确的来源引用、版本和校验结果；费用、已发生的副作用和历史事件不会因分叉消失。

## 4. 继续执行所需的状态

检查点应能定位当前工作流位置、Node 局部进度、有效配置和插件版本、剩余预算、上下文资料及适用的工作区状态。分支可以引用这些状态来重建上下文，不必为每条分支复制完整对话；但缺少关键状态时只能查看历史，不能把它标为可继续。

分支树不会自动复制文件系统。写文件、运行测试、访问数据库或调用远程服务后创建的分支，继续执行前必须关联并核对快照、独立工作区或其他状态证明。结果未知的有副作用调用必须先按调用身份核对实际效果，不能仅因历史中缺少结果就重试。外部状态无法恢复或隔离时，分支可以作为历史查看点，或显式从当前现实状态派生一次新尝试，但不能把后者描述为从旧点精确继续。

## 5. Runtime 与插件职责

Runtime 统一管理会话、分支、工作流 Node 执行、模型调用、工具调用、事件和检查点的身份，并负责持久化、分叉、恢复和上下文读取。插件向 Runtime 报告自己的执行过程；插件不能创建脱离会话树的隐藏历史。

如果插件无法提供调用级报告，Runtime 应明确标出其分叉粒度只能到 Node 完成处。分支创建、检查点继承和外部状态核对仍由 Runtime 负责，插件只提供其声明的能力和实际结果。

## 6. 待确认事项

- 分支如何分配模型、工具、时间和总预算：共享会话总额、每分支单独上限，或两者结合。
- 初版是否允许多个分支同时运行；并行运行需要额外解决工作区隔离和预算并发更新。
- 大型上下文、产物和证据在祖先分支中的保存与引用范围。
- 用户选择“从当前状态另试”时，界面和记录如何清楚标注它不是从旧状态恢复。
